This is a CMake project and all the files generated by the build are under the "build" subdirectory.
You **MUST** avoid accidentally globbing into the "build" directory unless strictly necessary.
Main subdirectories in this workspace:
- "src" contains the main product source code.
- "tests" contains the unit tests.
- "data" contains some files used at runtime, like system prompts.
- "src/Tools" contains the implementation of AI agent tools.
All source files must end on a newline.
The code complies with the C++23 standard, and you should always prefer its more modern features like `std::ranges` and `std::format`.

Which prompt file a piece of agent behaviour belongs in matters, because the harness assembles them at runtime and a rule in the wrong one binds the wrong roles.
- "data/MainSystemPrompt.txt" is the orchestrator's own instructions, and "data/ImplementSystemPrompt.txt" and "data/ResearchSystemPrompt.txt" are the per-role subagent instructions.
- "data/CommonSystemPrompt.txt" is appended to all three, so it must hold only behaviour that is identical for a role that can edit files, a role that can only read them, and the orchestrator; guidance only one of them can act on never goes there.
- Guidance about how work may or may not be changed in scope belongs in the orchestrator prompt and, in a form limited to its narrower powers, in the implementer prompt; the research agent cannot modify the workspace at all, so it needs no such rule.
