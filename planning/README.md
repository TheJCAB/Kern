# Planning directory

This directory holds proposals and pending work for Kern, one document per plan. These documents describe intended future behaviour, not the behaviour of the code in this repository; they are not documentation of current behaviour, and nothing here is a source of truth for it. `README.md` is the index and the rulebook, not a plan.

## Managing this directory

- Keep this file short: it lists what is pending and says how the directory is managed. Any rationale, trade-off, cost analysis or ordering belongs in the plan that contains the design.
- One plan per file, and each plan is self-contained: a reader of a single plan should not need another one to know what it proposes.
- File names are `NN-kebab-case-slug.md`, with a two-digit number that only ever grows. Take the next free number and never renumber, insert or reuse one, because the numbers are the shorthand used in prose ("design 03").
- Every plan opens with `# Title`, then a `Status:` paragraph (`proposal, nothing implemented.`, `in progress`, or `implemented`), then a `Related designs:` sentence naming, with relative links, the plans it depends on or coordinates.
- Cross-references between plans use relative markdown links to the file (for example `[02 Memory tool](02-memory-tool.md)`) and source anchors as `path:line`. Never refer to a file by an absolute path or a bare number alone.
- A plan that coordinates several others — shared mechanisms, ordering, common implementation constraints — is a plan of its own, not a section of this file: it links to the plans it coordinates and each of them links back. [`05-memory-and-context-programme.md`](05-memory-and-context-programme.md) is the current example.
- When a plan is finished or abandoned, remove it from the list above and record the outcome in the same change; do not leave a stale entry claiming work is pending.
- Nothing in this directory may be generated by the build or written under `build/`, and every file ends with a newline.
